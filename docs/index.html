What this is

google-services-mcps is a suite of Model Context Protocol servers for Google products. Each product is one plugin in one marketplace, and each plugin runs one local MCP server with the same name. The agent starts the server over stdio, the server calls Google's APIs with the credentials you give it, and every tool name starts with mcp__plugin_<product>_, so a call always traces back to one product.

The same servers run in four harnesses. Claude Code installs them as plugins from the google-services-mcps marketplace. The gsm installer writes the same servers into a Codex, an OpenCode or an Antigravity configuration. There is no build step and no server of the suite's own: the servers run on your machine, as you.

One plugin per product

A single plugin for every Google API would load thousands of tool definitions into every session. This suite splits the work by product instead, so you install only what you use.

  • Install only what you use. Each plugin adds its tools to your session. Fewer plugins means less to load.
  • Each product has its own login group. Products in one group share one login. A Search Console login does not reach Gmail.
  • Switch one server off for a session. Use /mcp to turn a server off and on again without uninstalling it.
  • Tool names show the product. Every tool name starts with mcp__plugin_<product>_, so a call always traces back to one product.

How the pieces connect

The marketplace lists the plugins. A plugin holds one MCP server, a consent hook for Claude Code, a tool map and a skill. The server reads your tokens from the token directory and calls Google over HTTPS. The hook runs before each tool call and asks before a change.

Codex, OpenCode and Antigravity have no approval hook in this suite. A client that cannot ask for approval is refused every change, so nothing runs without a confirmation. The full model is on the architecture page.

Install

One command installs the suite and Gmail for Claude Code. It adds the marketplace and installs the gmail plugin for your user account, the default scope. It checks what Claude Code needs first and writes nothing until that is in place.

Install Gmail for Claude Code

npx google-services-mcps install --agent claude --plugin gmail

Run the command with no arguments in a terminal to open a guided menu instead. The menu asks for the agent, the products and the scope, shows the exact command it will run, and previews it with --dry-run. Every route and every flag is on the install page.

Safe by default

The controls apply in order, and one failing layer does not let a change through.

  1. Token scopes. A login asks only for the scopes of its profile: readonly (the default), readwrite, full, or an exact list. Google rejects any call outside them.
  2. Tool registration. A write or destructive tool is listed only when Allow write tools is on. It is off by default.
  3. Approval gate. In Claude Code a PreToolUse hook asks before every change. The hook never allows a call, so your own permission rules still apply. Destructive actions ask twice: once in the hook and once in an Approve this action? form.
  4. Confirmation setting. every-change is the default. destructive-only asks only before deleting, sending, sharing, publishing and the other destructive actions. off asks for nothing, and deny rules still apply.
  5. Policy file. policy.json in the token directory holds allow, ask and deny rules. A matching deny always wins.
  6. Audit log. Each gated action writes one JSON line with the time, tool, method, decision and outcome, and a hash of the arguments, never the values.

The configuration page lists the settings by name, and the troubleshooting page covers the messages the suite prints.

Status

The suite is in beta. The code is built and tested offline: the unit and build tests pass, a smoke test starts all 23 servers over stdio, and Claude plugin validation passes for the marketplace and the Gmail plugin. Live Google accounts have been tested for three products only: gcloud (the project readiness check and enabling APIs), gsc (reads and a live login check) and gmail (reads, on six accounts). Nothing else has run against a real account, and no mail has been sent.

Test one product at a time, starting with a read, on an account where a mistake does no harm. The quick start walks through the first server.
