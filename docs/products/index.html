Reference

Products

The suite has one plugin per Google product. Each product id is also its plugin name and its MCP server name. This page is generated from the plugin folders at build time, so the list, the descriptions and the tool counts come from the manifests, not from a typed table.

The tool count is what the product's server registers: the plugin's tool map without the runtime tools of other sign-in kinds, and, for the service-account group, without tools the key's fixed scopes never cover. A product's page lists every registered tool, its OAuth scopes, its APIs and its login group.

What a product page shows

Each product page is generated from the plugin folder, so it cannot drift from the code. It shows the install command, the APIs the server carries and the gateway APIs it can reach, every tool the server registers with its safety class, the OAuth scopes in the plugin's scope file, and the plugin's own metadata: its name, server, version, login group and options.

  • Tools are listed with the class the plugin's tool map gives them: read, write, destructive or dynamic.
  • Scopes come from the plugin's scopes.json, grouped by API. A login asks only for the scopes of its profile.
  • APIs come from the plugin's servers.json, which the build generates from the product map.
  • The login group decides which kind of credential the product uses.

Status

The suite is in beta. Three products have run against live Google accounts: gcloud, gsc and gmail. The others are built and tested offline only, so test each one with a read first, on an account where a mistake does no harm.

Login groups

Products in one group share one login. Log in once per group, with the products of that group that you use.

Choosing

Install a product only when you have a use for it. Start with a read-only login and Allow write tools off, add one product at a time, and turn on changes later for one product at a time. gadmin and gads can change real users and spend real money, so they carry the highest risk.

The install page has the commands. The configuration page lists the settings by name.
