# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

google-services-mcps is a set of MCP servers for Google products, packaged as Claude Code plugins in one marketplace, with an installer (`gsm`) for Codex, OpenCode and Antigravity (`agy`). One plugin per product (23 in total), and each plugin runs one MCP server with the same name as the plugin. Public repository: https://github.com/FiredMosquito831/google-services-mcps (owner FiredMosquito831). Licence Apache-2.0 with NOTICE. The website is GitHub Pages from `site/`.

Status: built and tested offline (644 tests on Windows: 641 pass, 3 skipped; the Linux count is checked before each release), smoke test over all servers, plugin validation. The npm package is `google-services-mcps`, one package. 1.1.0 is the latest release under that name (GitHub release v1.1.0, published with provenance). The scoped name `@firedmosquito831/google-services-mcps` is deprecated (all five versions, 2026-10-16). The owner ran `npm deprecate` in a terminal, because it needs a one-time password. The `npm` workflow publishes the package when a GitHub release is published (trusted publishing, with provenance). The gcloud server was checked live with an application-default login on a danubelabs.net Google account (readiness check and enabling APIs). The other servers have not run against live Google accounts. Treat any other live claim as unverified until a live test has run.

## Stack and versions

- Node 20 or newer (`engines`); developed on Node v24.6.0. npm 11. The publish workflow uses Node 24 and npm 11.5.1 or newer (trusted publishing).
- TypeScript `~5.9.3` (not 7). Compiles to `dist/` (ESM, NodeNext).
- `@modelcontextprotocol/sdk` 1.29.x, `zod` ^3.25 (v3 API), `google-auth-library` ^11, per-API `@googleapis/*` packages (admin, apikeys, calendar, cloudresourcemanager, drive, gmail, searchconsole, serviceusage, webmasters), `esbuild` ^0.28 (bundles everything; plugins need no `node_modules`).
- Dependencies are dev-only in `package.json` on purpose: the bundles are self-contained.
- Claude Code CLI (`claude plugin ...`); the installer shells out to it.
- One npm package, `google-services-mcps`. The `files` list in `package.json` is the whole shipped payload: `gsm.mjs`, `plugins/`, `config/`, the install scripts, README, LICENSE, NOTICE and `docs/TUTORIAL.md`.

## Commands

Run from the repository root.

- `npx tsc --noEmit`: typecheck.
- `npx tsc -p tsconfig.json`: compile to `dist/`. Tests import from `dist/`, so compile before running a single test file.
- `npm run build`: bundle the 23 plugins and the root `gsm.mjs` (`scripts/bundle.mjs`). Rewrites `plugins/**`.
- `npm test`: compile, then `node --test tests/*.test.mjs`.
- One test file: `npx tsc -p tsconfig.json` then `node --test tests/gate.test.mjs`.
- `node scripts/smoke.mjs`: starts every bundled server over stdio (needs a build).
- `claude plugin validate .` and `claude plugin validate plugins/<id>`: manifest checks.
- Generators (never hand-edit their output): `npm run surfaces` (`docs/SURFACES.md`), `node scripts/gen-capabilities.mjs` (`docs/CAPABILITIES.md`, `docs/capabilities/`), `node scripts/gen-readme.mjs --check` (README products block), `node scripts/gen-site.mjs` (site product section, sitemap), `node scripts/gen-servers.mjs` (`config/servers.json` from `config/products.json`), `node scripts/build-catalog.mjs` (`data/catalog.json`), `node scripts/snapshot-discovery.mjs` (`data/discovery/`, `data/scopes.json`).
- `npm run pack:check` or `npm publish --dry-run --access public --ignore-scripts`: what would be published. Without `--ignore-scripts`, `prepublishOnly` runs the build and tests.
- Bump: `node scripts/bump.mjs patch|minor|major` (or `X.Y.Z`) moves `package.json` and `package-lock.json` together. Release: publish a GitHub release `vX.Y.Z` (not a draft) after the bump is on main. `.github/workflows/npm.yml` checks the tag against `package.json` and publishes the package. Nothing publishes on a push.
- Installer, always with a temp home in tests: `node gsm.mjs install --agent <claude|codex|opencode|agy|all> --plugin <id,...>|all [--scope global|project|local] [--path <dir>] [--dry-run] [--home <dir>]`, and `node gsm.mjs uninstall ...` or `uninstall --all --yes`, `node gsm.mjs list`.
- For Claude Code tests, set `CLAUDE_CONFIG_DIR` to a fresh temp folder. This isolates Claude's own state (verified).

## Architecture (big picture)

Four layers, and the generated plugin folders are the join point.

1. **Product map** (`config/products.json`, the source of truth). Each product has a group, a server name (equal to its id), a curated module or none, a list of generated APIs (per-method tools, capped at 350 tools per server) and a list of gateway APIs. `config/servers.json` is generated from it.
2. **Tool generation.** Curated tools are hand-written in `src/servers/*.ts` (each exports `buildTools(cfg)`). Generated per-method tools come from Google's Discovery documents (`src/core/discovery/`, snapshots in `data/discovery/`). Gateway tools (`api_search`, `api_describe`, `api_call`, in `src/core/gateway.ts`) reach every other API of the product through the catalog (`data/catalog.json`, 533 entries and about 29,000 methods). `scripts/bundle.mjs` merges curated, generated and gateway tools into one entry per server.
3. **Runtime** (`plugins/<id>/`, generated). `servers/<id>.mjs` is the MCP server. `hooks/hooks.json` runs `bin/gsm-hook.mjs` before each call to the plugin's tools. `tool-map.json` and `method-kinds.json` tell the hook the safety class of each tool and method. `.mcp.json` passes plugin options (allow_writes, confirmation, token_dir) to the server as env vars.
4. **Installer** (`src/cli/`, bundled into `gsm.mjs` at the root and into each plugin's `bin/`). Installs into Claude Code via the `claude plugin` CLI, and into Codex, OpenCode and agy by writing their config files. Each install copies the product's files to `<home>/.google-services-mcps/runtime/<product>/` and points the agent config there.

**Consent and safety flow.** Reads never prompt. Write and destructive tools are only listed when `GSM_ALLOW_WRITES=true`. Writes prompt through the hook. Destructive tools prompt twice: the hook, then an MCP elicitation with an exact preview from `ctx.gate()` (`src/core/approval.ts`). Clients with neither hooks nor elicitation fail closed. Policy rules (`policy.json` in the token directory) allow, ask or deny by tool or method. Audit lines hold a hash of the arguments, never the values. The model cannot bypass any of this: there is no model-controlled `confirm` argument, and it must not be reintroduced.

**Scopes.** Logins request a profile (`readonly` default, `readwrite`, `full`, or an explicit list). Tools the stored token cannot use are not registered. Logins merge with the stored scopes of the account named with `--account` (`auth_login`'s `account`), keeping only scopes a server of the group uses; with no account nothing is merged; `--replace` drops them. Gateway methods count toward login coverage too (`src/core/scopes.ts`, `src/core/registry.ts`).

**Shared rules that live in two places.** `src/core/discovery/methods.ts` (`classifyMethod`) and `src/cli/method-kinds.ts` (a copy, used by the plugin bundles) must agree. `tests/cli-surface.test.mjs` checks every catalog method.

## Rules (repository-specific)

- Versioning: a commit on `main` that changes a production file bumps the version in the same commit, with `node scripts/bump.mjs patch|minor|major`. Production files: `src/**`, `config/**`, `scripts/bundle.mjs`, `scripts/install.*`, and `package.json` (name, bin, files, dependencies). Tests, docs, `site/`, README, this file and `.github/**` need no bump on their own. A commit that mixes both still bumps.
- Semver: PATCH for fixes, refactors with no visible change, dependency updates and install fixes. MINOR for new commands, options, tools, products or behaviour. MAJOR for breaking changes: removed or renamed commands, options, environment variables or config keys, or anything users must act on. When unsure between PATCH and MINOR, pick PATCH for a fix and MINOR for new capability.
- Release, in order: (1) the bump (`node scripts/bump.mjs`) and the `CHANGELOG.md` entry for the version go in the same commit as the change; (2) push to `main` with the owner's go-ahead; (3) publish a GitHub release `vX.Y.Z` (not a draft) on that commit, with the changelog entry as its notes. The release starts the npm publish. A push does not. Plugin manifests keep `MANIFEST_VERSION` in `scripts/bundle.mjs` and change only when plugin content changes. Check afterwards: the publish run passed, the log shows `+ google-services-mcps@X.Y.Z`, and the registry's `latest` is X.Y.Z.
- Keep this file current. When the stack, a command, a rule, a preference or a non-obvious fact changes, update the matching section in the same change. Correct a stale line rather than adding a contradiction.
- Do not hand-edit generated output: `plugins/**`, `gsm.mjs`, `dist/`, `build/`, `config/servers.json`, `docs/SURFACES.md`, `docs/CAPABILITIES.md`, `docs/capabilities/`, the README products block, the site product section. Change the source (`config/products.json`, `src/**`, `scripts/**`) and regenerate.
- Tool names must fit 64 characters including the prefix `mcp__plugin_<plugin>_<server>__`. Budget = 49 minus the lengths of the plugin id and the server name. Keep plugin ids short; the generator enforces the budget for generated names.
- Writes and destructive actions go through `ctx.gate()`. Never call a Google API that changes state from a path that skips the gate.
- Anything that reads a method's kind must use `classifyMethod`. A POST counts as a read only for the narrow verb list and exact names in `src/core/discovery/methods.ts`. Credential names (token, credential, secret, password, authorization, key) are always writes.
- Scopes merge by default, per account. A login merges the stored scopes of the account it names (`--account`, `auth_login` `account`, sent to Google as `login_hint`) and only those a server of the group uses (`groupScopeUniverse` in src/cli/scopes.ts; a plugin reads its group's list from `groupScopes` in its servers.json, written by the bundle). Never merge another account's scopes (the default account's, say) into a login, and never send `include_granted_scopes`. A save never takes usable scopes away from an account unless that account was named and signed in, or the user passes `--replace`; otherwise the login saves nothing and says how to retry (src/cli/login.ts).
- Credentials: only `gsm status --check`, `gsm doctor` and the health tool with `live: true` ask Google about a stored login (src/core/grant-check.ts). A read tool never does. A refused login's message names Google's `error` and `error_subtype`, tells a reauthentication (`invalid_rapt`) apart, and points to `auth_login` first, the terminal second. Logout revokes the grant first (`--local-only` skips that). Every message about a login is redacted with the token and the client secret before it is shown.
- Pre-login: the OAuth groups (workspace-user, searchconsole, business, developer) register only tools that need no scope, plus `auth_status`, until a login exists: an account of the group, or the ADC login (src/core/tools.ts, `loginSourceOf` in src/core/auth.ts). The apikey group has its own key.
- ADC is a sign-in option for every OAuth group (src/core/adc.ts). `auth_login` without `method` returns the two options with their pros and cons, and the person chooses. Tests that start a sign-in pass `method`. The suite reads the ADC file's type, quota project and a SHA-256 of its refresh token. It never returns, prints or writes the token, and never writes to the ADC file. `adc.scopes.json` in the token folder records the group, scopes and hash of the last ADC login the suite made. A group uses ADC only when none of its accounts is signed in here (`adcSourceFor`). A group on ADC gets its scopes from the record, and a record whose hash no longer matches the file is ignored.
- Curated tools that return a secret are writes, as their generated copies are. config/tool-kinds.json holds the kind of every Discovery method that is not a plain verb, including GET methods that change state. A test checks both.
- Every server has runtime tools: `health` everywhere, and the sign-in tools (`auth_setup_client`, `auth_login`, `auth_status`, and `auth_setup_admin` for the admin server) where a Google sign-in exists. runServer adds them (src/core/tools.ts, src/core/inchat-login.ts). They must also be listed as reads in the built tool map (dumpTools). A tool missing from the map is treated as destructive by the hook, so every call would ask.
- Several accounts per Google group: a token file per account, listed in accounts.json (src/core/accounts.ts). A tool call names its account with the `account` argument. The wrapper in tools.ts takes it out and sets the account for the handler (src/core/account-context.ts), so it never reaches Google. Clients are made per account by getAuthClient, which caches them per token file. Do not cache a Google client in a server module.
- The token folder is created with ensureTokenDir (src/core/acl.ts), never with a bare mkdirSync: on Windows it limits the folder's access list.
- Secret files (the token files, the client secret and its backups, the API key, the Ads developer token) are read and written only through src/core/secret-files.ts (`readSecretText`, `writeSecretText`, `secretFileExists`, `removeSecretFile`). Never call fs on them directly: the store in use may hold them. The store is chosen by GSM_TOKEN_STORE, then `store.json`, else plain files (mode 0600). `secrets.json` lists the stored names, never content. `gsm protect` / `protect --off` move them (src/cli/protect.ts). A value is read back before its plain copy goes, and a failed run is rolled back. Keep the secret out of argv: the store helpers pass it on stdin (src/core/secret-store.ts).
- The service-account group (gplay, gmerchant) uses a key set up with `setup-service-account` or the chat tool `auth_setup_service_account`. Only the key's path is stored (service-account.json). Its scopes are fixed (SERVICE_ACCOUNT_SCOPES in src/core/auth.ts). Its tools register only after setup, like the OAuth groups. `GOOGLE_APPLICATION_CREDENTIALS` may hold the key instead.
- gmaps is in the apikey group (its key is apikey.json, shared with gsearch).
- Project readiness: READINESS_GROUPS in src/core/readiness.ts lists the services each login group's products need. Tests check it against config/products.json, so when a product's APIs change, change the list too. The gcloud server exposes `project_readiness` (read) and `project_enable_missing` (write, batches of 20). The consent screen, publishing, test users and the Desktop OAuth client have no API we can use: the readiness output links to the console pages for them.
- Public site: `site/` deploys to GitHub Pages on a push to main that touches `site/**` (`.github/workflows/pages.yml`). The canonical host is https://google-services-mcps.danubelabs.net/ (`SITE_URL` in `scripts/gen-site.mjs`). The canonical, og and twitter URLs in `site/index.html` and `site/privacy.html`, and the `Sitemap:` line in `site/robots.txt`, use the same host. The sitemap lists the home page and `privacy.html` on that host, because Search Console ignores entries on another host. The github.io address serves the same files. `site/privacy.html` is the privacy policy for the Google OAuth consent screen. The custom domain `google-services-mcps.danubelabs.net` is a DNS-only CNAME in Cloudflare (zone danubelabs.net) to `firedmosquito831.github.io`, and the owner set it in the repository's Pages settings. The repo has no `site/CNAME`, so check the custom domain in the Pages settings after each deploy. `scripts/gen-site.mjs` writes only `index.html`, `sitemap.xml` and `og.png`, so it keeps `privacy.html`.
- Installer tests always pass `--home <temp dir>`. Claude tests always set `CLAUDE_CONFIG_DIR`. Never let a test write into the real home folder or the real Claude config.
- Never commit tokens, client secret files, `HANDOFF.md`, `reference/`, `session/` or `.remember/` (all gitignored). Scan before any push that might expose something new.
- In user-facing docs (README, `docs/`, `site/`), show the npm command: `npx google-services-mcps <command>`, or `google-services-mcps <command>` after a global install (`gsm` is the same command). Keep `node gsm.mjs <command>` for clone and development instructions only, and for the messages printed from a repository (the code writes `node gsm.mjs`, and `invocationText` replaces it at print time).
- Do not publish to npm, push, force-push, change repository visibility, deprecate a package, or send anything outward without the owner's explicit go-ahead in the current conversation. Committing locally is fine.
- Commit messages end with `by FiredMosquito831`. Commit author is the GitHub no-reply address (repository-local `user.email`).
- On Windows, write commit messages to a file and use `git commit -F`. Redirect git's CRLF warnings with `2>$null`.

## Learnings

Append a dated bullet whenever you learn something non-obvious about this repository. Keep it short and true.

- 2026-10-15: `git filter-branch` keeps the original commits under `refs/original`; delete those refs and run `git reflog expire --expire=now --all && git gc --prune=now` before judging whether an old value is still present.
- 2026-10-15: `npm publish --dry-run` runs `prepublishOnly` (build and tests). Use `--ignore-scripts` for quick dry runs.
- 2026-10-15: the installer records installs in the gsm home (`runtime/installs.json`) even when `CLAUDE_CONFIG_DIR` is set. A test once wrote into the real home. Always pass `--home`.
- 2026-10-15: the Google Discovery directory lists only preferred versions. The Admin SDK is one name (`admin`) with several versions, and some APIs (cloudquotas, generativelanguage, googleads v26) need direct discovery URLs. Webmasters is covered by the `searchconsole` document.
- 2026-10-15: Discovery endpoints that fail (contentwarehouse and poly return 502; area120tables, datalabeling and mybusinessqanda return 404) stay unassigned in `config/products.json` with a reason.
- 2026-10-15: plugin bundles need the `createRequire` banner, because some dependencies are CommonJS.
- 2026-10-15: Google Ads developer tokens were sunset on 2026-09-09. Access now belongs to the Cloud project of the OAuth client, and the suite treats the token as optional.
- 2026-10-15: Custom Search JSON API is reported closed to new customers and to be discontinued on 2027-01-01. Not confirmed; check in the Cloud console before relying on it.
- 2026-10-15: a local directory marketplace makes Claude read plugin files straight from the repository (per Claude Code docs). A GitHub marketplace uses a copy in the plugin cache.
- 2026-10-15: subagent reports were wrong more than once (stale counts, a flag that did not exist). Verify the state yourself before reporting it.
- 2026-10-16: in Git Bash on Windows, `curl` can resolve to `C:\Windows\System32\curl.exe`, which cannot write to a `/tmp` path. `scripts/install.sh` passes curl a `cygpath -w` path for that reason. Regression test `4c` puts System32 first on PATH.
- 2026-10-16: `.gitattributes` has `* text=auto eol=lf`. The owner's Windows git has `core.autocrlf=true`, and `install.sh` must stay LF for Linux `sh`.
- 2026-10-16: `npx <file.tgz> ...` exits 0 and runs nothing. Test a tarball with `npm install -g --prefix <dir> <tgz>` (then `<dir>\gsm.cmd`) or `npm exec --package=<tgz> -- gsm ...`.
- 2026-10-16: in `cmd`, `move` of a folder from `%TEMP%` to another drive fails with "Access is denied". `scripts/install.cmd` uses `xcopy` for that step. Test `5. cmd: ... another drive` runs when a second drive exists.
- 2026-10-16: `npm publish` from this shell stops at `EOTP` (browser approval). The owner runs `npm publish --access public` in a terminal and approves in the browser. `prepublishOnly` runs the build and the tests first (about 6 minutes).
- 2026-10-16: on this machine the `sh` on PATH is msys64's, not Git for Windows'. In a test, the `sh` that a piped `curl | sh` starts did not see `USERPROFILE`, `CLAUDE_CONFIG_DIR` or `GSM_DIR` exported by the parent script. The cause was not fully established, and that run wrote a marketplace and folders into the real profile. Before a one-liner test, probe the environment inside the pipeline, and check the real Claude config afterwards with `claude plugin marketplace list`.
- 2026-10-16: the runner (`src/cli/exec.ts`) never uses a shell, and Node cannot start a `.cmd` or `.ps1` shim without one. On Windows, npm, codex and opencode are shims, so `src/cli/requirements.ts` runs them as `cmd.exe /d /c <program> <args>`. Tests of the requirement check run a fake runner, and give `requirements` a stub in the install environment, so they do not depend on this machine's programs.
- 2026-10-16: every printed command starts with `invocation()` (`src/core/invocation.ts`). The `node gsm.mjs` text in messages is replaced at print time, so the same message says `npx google-services-mcps` from npm, `node "<full path>"` from another folder, and `node gsm.mjs` in the repository. Add new messages with `node gsm.mjs` and do not build the prefix by hand.
- 2026-10-16: the interactive layer (`src/cli/prompt.ts`, `src/cli/guided.ts`) only runs in a terminal (stdin and stdout are TTYs). A guided flow builds the same argv a person would type, shows it, and runs it through the same dispatcher. Keep new guided steps the same way, and never put a secret in an argv.
- 2026-10-16: the Claude Code marketplace is the repository folder only when it is a git checkout (`checkoutRootFor` in `src/cli/paths.ts`). An npm package or a zip download has the same files without `.git`, and npm's package has no root `.claude-plugin/marketplace.json`, so those installs use `FiredMosquito831/google-services-mcps` on GitHub. The published 0.1.1 predates this rule, so it needs `--marketplace` for Claude Code.
- 2026-10-16: a test that writes an executable fake (such as a fake `node` on PATH) must `chmod` it. Linux skips a non-executable PATH entry, and the test then runs the real program.
- 2026-10-16: to run the suite on Linux, use WSL (Ubuntu 24.04 here): copy the tree and `.git` into a fixed folder under `$HOME`, then `npm ci && npm test`. The bootstrap tests call `git archive`, which fails without `.git`. Do this from a script file with `set -u`. A copy that never happened left `$NEW` empty, and the repository was extracted into the WSL home folder, which holds the owner's own files. Check every destination variable is set before a `tar -x`, and never extract into `$HOME`.
- 2026-10-16: a published GitHub release starts the npm publish (`.github/workflows/npm.yml`). A push to `main` does not. The tag must equal the version in `package.json`, and a version already on npm is skipped. A release runs the workflow file at its tag's commit, so the workflow must exist there. The release trigger has run for v0.1.2 and v0.1.3.
- 2026-10-16: a publish that fails with `E404 ... PUT` (no permission) is a login problem, not a name problem. `npm login` in the terminal fixed it for `google-services-mcps` (the name is free, and `google-services-mcp` without the "s" is a different package). Do not assume a name is blocked from one 404.
- 2026-10-16: npx and npm cache a package's metadata. After a publish, a `No matching version found` can stay until `npx --prefer-online <package> ...` (or `npm cache clean --force`).
- 2026-10-16: trusted publishing is set on each package's page on npmjs.com, so the package must exist first. The first publish of a name is manual (the owner's terminal, with two-factor). After that `npm.yml` publishes each new version. The `npm.yml` workflow was copied from ase-moodle-mcp.
- 2026-10-16: the package is one name now, `google-services-mcps` (`NPM_PACKAGE` in `src/core/invocation.ts`). The scoped name was the installer, and the unscoped name was a thin wrapper that depended on it. Deprecating the scoped name while the wrapper depended on it would print a deprecation warning on every `npx google-services-mcps` install, so the wrapper was removed first. Rule: deprecate a package name only after nothing you ship depends on it.
- 2026-10-16: a publish is accepted before it is visible. npm printed "Your package is being processed and may take a few minutes to become available". The unscoped name was visible at once; the scoped name took a few minutes. A green step is not proof: check the registry (`https://registry.npmjs.org/<name>/<version>`) and the `+ name@version` line in the log.
- 2026-10-16: `gh run list --workflow` returns the newest run of an event. Right after a release, it can return the previous release's run. Select the run by `headSha`.
- 2026-10-16: npm printed "npm tokens that bypass 2FA are being restricted for account changes and direct publishing" during a publish. Trusted publishing uses no token, but a token fallback (as in my-claude-code) may stop working.
- 2026-10-16: PowerShell's `ConvertFrom-Json` fails on `package-lock.json`, which has an empty-string key (`""`). Edit JSON with `node` instead.
- 2026-10-16: `npm deprecate` needs a one-time password like `npm publish`. From this shell it prints a "deprecating" notice for each version, then stops at `EOTP`, and the registry shows no flag. Check the registry (`versions.<v>.deprecated`) before saying a deprecation happened. The owner runs the command in a terminal.
- 2026-10-16: `gsm install --home <dir>` is refused for `--agent claude`, which always uses the real Claude Code configuration. A dry run into a temp home must use codex, opencode or agy.
- 2026-10-16: `git add -A` picked up `bash.exe.stackdump`, an msys crash dump, in a docs commit. `*.stackdump` is in `.gitignore` now. Stage files by name when a crash has happened.
- 2026-10-16: the curated `cloud_apikey_reveal` was `read` while the generated copy of the same Google method (`getKeyString`) was `write`. Reads never prompt, so the key could leave without a prompt. Keep curated and generated kinds in step, and test both.
- 2026-10-16: Discovery marks `cloudbilling.organizations.billingAccounts.move` as a GET, and it changes state. A verb-based rule cannot catch that, so list such methods in config/tool-kinds.json.
- 2026-10-16: `icacls` lists `CREATOR OWNER` for an inherited entry. It is the owner placeholder, not a second reader, so the access check allows it (src/core/acl.ts). Use the well-known SIDs (`*S-1-5-18`, `*S-1-5-32-544`), which keep the names the same in every Windows language.
- 2026-10-16: google-auth-library reports a refused refresh token as `invalid_grant`, in the message or the response body. isInvalidGrant (src/core/auth.ts) reads both, and the refused login then gets the message that says how to log in again.
- 2026-10-16: a test that starts a callback must attach its promise handler before the callback is sent. Otherwise Node reports an unhandled rejection before the assertion runs.
- 2026-10-16: PowerShell string replacement in double quotes breaks template literals with backticks, and it once left `${invocation()}` unquoted in gateway.ts. Edit source with the Edit tool, or use single-quoted strings.
- 2026-10-16: writing config/tool-kinds.json with ConvertTo-Json drops its blank group lines. Insert a line as text instead.
- 2026-10-17: the tool list a Claude Code session shows can lag the plugin. In the session of 2026-10-17 the gmail server (0.5.0) had `auth_status`, `auth_login` and `accounts_list`, but the session's list had none of them. Check a server with the harness (`list`, `call health`) before reporting a tool as missing.
- 2026-10-17: `~/.claude/plugins/cache/google-services-mcps/<plugin>/0.1.0` is an old copy. A local-folder marketplace reads the repository (`claude plugin list` shows "Read from"), so the cache is not the running version.
- 2026-10-17: google-auth-library's `Credentials` type has no `account` field, but a saved token carries one. `saveAccount` takes `Credentials & { account?: string }`.
- 2026-10-17: `gcloud auth application-default login` with its built-in client grants only the cloud scopes. Other scopes need `--client-id-file` with our own client (gcloud reference). With that flag, the client's project becomes the quota project. The built-in login has none unless one is set, which gives the "Cannot find a quota project" warning.
- 2026-10-17: the ADC file is one per machine (on Windows `%APPDATA%\gcloud\application_default_credentials.json`). A new ADC login replaces it, so a record made for one group does not cover another.
- 2026-10-17: the discovery layer used to cache one client per group for the life of the process, so a new login was not used until restart. Only getAuthClient caches now (per account, or per group for ADC), and it forgets the ADC clients after a new ADC login.
- 2026-10-17: on Windows the gcloud CLI is `gcloud.cmd`, and its install folder has a space. The sign-in starts it as `cmd.exe /d /s /c "<path>" <args>` with `windowsVerbatimArguments` (src/core/inchat-login.ts).
- 2026-10-17: `health` said "not logged in" for cloud while cloud calls worked through ADC, because it checked only the OAuth token. Fixed in 0.6.0: `loginSourceOf` counts both.
- 2026-10-17: a keychain cannot list its entries, so the suite keeps the names it stored in `secrets.json`. `gsm protect --off` needs that list.
- 2026-10-17: PowerShell writes its profile data under USERPROFILE. A test that points USERPROFILE at a token folder finds an AppData folder inside it. Point the fake home at a subfolder.
- 2026-10-17: a default parameter also applies when the caller passes undefined. A test that wants "no field" must say so with a flag, not with undefined.
- 2026-10-17: Google Play's scope is androidpublisher, and Merchant's is content. Play and Merchant both accept a service account. The Merchant quickstart says to give it Admin access in Merchant Center.
- 2026-10-17: the usage errors of `gsm` exit with code 2. A refused key is a usage error, so a test expects 2.
- 2026-10-18: the IAP OAuth brand and client API (`iap oauth-brands`, `iap.googleapis.com` brands) is deprecated and shut down. Google has no API we can use for the consent screen, publishing, test users or a Desktop OAuth client. The `gcloud alpha auth oauth-clients` command group is not installed on this machine, and installing it needs an interactive terminal.
- 2026-10-18: serviceusage's batch enable is atomic per request, so one bad service name fails the whole request. We send at most 20 per request, and report a failed request without stopping the others.
- 2026-10-18: google-auth-library's `getTokenInfo` returns `scopes` (an array) and `expiry_date` (milliseconds). The raw tokeninfo endpoint returns `scope` (a string) and `expires_in`. Until 1.0.1 the live check read only the raw names, so every granted scope looked missing. The unit tests used the raw shape and passed. Test against the library's shape; `readTokenInfo` in src/core/grant-check.ts reads both.
- 2026-10-18: `gh release create --target` needs the full 40-character commit SHA. A short SHA returns HTTP 422.
- 2026-10-18: a background `gcloud auth application-default login` that waits for its redirect on localhost:8085 died, and the browser showed "refused to connect". Run that sign-in in the prompt (the `!` prefix) instead.
- 2026-10-18: Google will not publish the OAuth app until the Branding page has an app name, a support email, a homepage URL and a privacy policy URL. The privacy policy is `site/privacy.html`, which GitHub Pages serves only after a push to main.
- 2026-10-18: Google rejects an OAuth app name that contains the word "Google" ("the app name does not comply with Google's requirements"). The app is named `g-services-mcps`.
- 2026-10-18: `scripts/gen-site.mjs` refuses to write (and writes nothing) while `docs/CAPABILITIES.md` or `docs/SURFACES.md` disagree with the plugins. Run `node scripts/gen-capabilities.mjs` and `npm run surfaces` first. A tool added to a plugin makes both stale.
- 2026-10-18: the consent screen's Verification Center needs the branding verified and then published ("Publish branding"); a verified result expires after 7 days. Google checked the homepage and privacy domains against the Search Console domain property. Its Data Access page classified `webmasters`, `webmasters.readonly`, `siteverification`, `siteverification.verify_only` and `indexing` as non-sensitive, so no verification is required for them. Check any Gmail scope in that page before adding it, because a restricted scope changes the answer.
- 2026-10-18: a Search Console sitemap's "indexed" count can read 0 while its URLs are indexed. `danubelabs.net/sitemap.xml` showed 206 submitted and 0 indexed, but four sampled URLs were "Submitted and indexed" in URL inspection. Check a sample with URL inspection before reporting the count.
- 2026-10-18: a Search Console sitemap can only list URLs on its own host. Our sitemap listed the github.io address from the custom domain's sitemap, so it was wrong for that host.
- 2026-10-17: a group's default must survive a second sign-in. A one-account registry with no stored default made the second account the default until `saveAccount` kept the first one (test: "the first account of a group is its default").
- 2026-10-29: `include_granted_scopes` made Google return every scope the account had granted the client's project, and the login stored them all, so Gmail tokens carried Cloud and Search Console scopes (21 scopes on every account). Google says incremental authorization is not supported for installed apps. The login merged the default account's stored scopes into every sign-in too. Both are gone in 1.1.2.
- 2026-10-29: a plugin's servers.json lists only its own server, and the CLI reads it with its own loader (`loadRegistryFile` in src/cli/products.ts), not `loadRegistry`. A group-wide fact a plugin needs (the group's scopes) must be written into each plugin's servers.json by the bundle, and read by both loaders.
- 2026-10-29: cloud-platform is a workspace-user scope too (16 gcontacts health tools list it, and the readwrite profile picks it), so the group filter keeps it in a Gmail token of the same account. To drop it, sign in with `--replace`.
- 2026-10-29: Workspace's Google Cloud session control (Google's default 16 hours since 2026-09-16) refuses a refresh with invalid_grant and error_subtype invalid_rapt. google-auth-library then puts Google's answer, as JSON, in the error message. `grantRefusalOf` (src/core/auth.ts) reads both places and shows only `error` and `error_subtype` (short codes; anything else is left out). Every refusal used to read "expired ... Testing 7 days".
- 2026-10-29: getAuthClient caches a client per token file with a SHA-256 of its refresh token and rebuilds it when the file holds another one, so a new sign-in is used without a restart. `forgetUserClients` also clears the OS-store read cache (src/core/secret-files.ts), which hides a token another process stored; a token that is not found is not cached. The refresh listener writes only while the file exists and still holds the client's refresh token.
