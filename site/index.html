What you get

One plugin per product

23 plugins, one for each Google product. Install the ones you use, and turn each server on or off for a session with /mcp.

Safe by default

Reads never ask. Changes and deletions ask first, and write tools stay off until you allow them.

Full API surface

3,500+ tools, generated from Google's Discovery documents. Each method of a generated API is one tool.

Gateway for every API

The other APIs of each product, 396 in all, are reached through three tools: api_search, api_describe and api_call.

Login once per product group

One sign-in covers each login group. Name the account (--account, or account in the chat) and the login merges its scopes with the ones that account already holds for the group; --replace drops them.

Four agents, one suite

Works in Claude Code, Codex, OpenCode and Antigravity. The installers write the server entries for the three other agents.

Products

One plugin per product. Counts come from the build and are split by safety class: read, write, destructive and dynamic. Each install command adds one plugin from the marketplace.

Tools and methods

Install

One command installs the suite for an agent. The npm name is google-services-mcps; the old scoped name is deprecated. It checks what the agent needs first, declares the marketplace in the scope you choose, and records what it did. Nothing is written until the requirements are in place and you have confirmed.

Run it

  1. Install Gmail for Claude Code. No clone, no build and no global install. The first run downloads the package.

    npx google-services-mcps install --agent claude --plugin gmail

  2. Or use the guided menu. In a terminal, run the command with no arguments. The menu asks the questions, shows each command before it runs, and previews it first.

    npx google-services-mcps

  3. Sign in once per Google group. Create a Desktop OAuth client in the Google Cloud console, give its JSON file to gsm, then log in. Gmail uses the workspace-user group.

    npx google-services-mcps setup-client path/to/client_secret.json
npx google-services-mcps login workspace-user

  4. Restart the agent and check that gmail is connected (in Claude Code, run /mcp).

What it does

  1. Checks the requirements of the agents you chose: Claude Code, Codex, OpenCode, and git when the marketplace comes from GitHub. A missing one stops the install, and the message names the command that installs it.

  2. Installs what is missing, if you ask (--install-missing, or yes in the menu). npm installs Claude Code, Codex and OpenCode. git comes from winget on Windows or Homebrew on macOS. On Linux, gsm shows the command, because git needs sudo.

  3. Claude Code: declares the google-services-mcps marketplace in the same scope as the plugin, then installs the plugin. A project install is shared when you commit .claude/settings.json.

  4. Codex, OpenCode and Antigravity: copies the server files to ~/.google-services-mcps/runtime/, and writes one entry per server into the agent's config file.

  5. Records the install, so list and uninstall know what gsm did. Uninstall removes only gsm's entries. Logins and tokens are never touched.

  • Search Console (searchconsole): gsc. Desktop OAuth client, then login searchconsole.

Safety

Six layers, checked in order. A failing layer does not let an action through.

  1. Token scopes. Google enforces them. A read-only login cannot write, whatever the plugin shows.
  2. Tool registration. A tool is listed only if the stored token can run it. Write and destructive tools need Allow write tools.
  3. Approval gate. Each change and delete asks first. The hook only asks or denies, and never allows. A delete, send or disable asks twice.
  4. Confirmation setting. every-change (default), destructive-only or off. Deny rules apply in every mode.
  5. Policy file. A matching deny always wins, then a matching ask, then a matching allow.
  6. Audit log. One line per gated action, holding a hash of the arguments. The arguments are never written.

Read the security model and its known limits before you turn on write tools.

Limits and costs

The suite is free. Google's APIs have quotas, some have costs, some need approval.

  • The servers add no charge of their own. Each call goes from your machine to Google, with your own OAuth client, API key or service account, so Google's rules apply to every call.
  • Quotas belong to a Google Cloud project or to an account. Check the Quotas page in the console before you rely on a number.
  • Rate-limit and unavailable responses are retried, up to three attempts in total. A quota that is used up does not clear by retrying.
  • Some APIs are closed or being retired. The Custom Search JSON API is reported closed to new customers.

Questions

Does it cost money?

The suite is free, and the servers add no charge of their own. Google's quotas, charges and approval rules still apply to every call. Each installed product also adds tool definitions to your Claude sessions, so install only what you use. See limits and costs.

Which accounts do I need?

Most products need a Google Cloud project with a Desktop OAuth client, and a Google account that can use the product. For a Workspace domain, use an Internal consent screen. A personal account needs an External consent screen that you publish, because an app left in testing loses its refresh token after 7 days. The workspace admin plugin needs a super admin email and a service account with domain-wide delegation. The search and web-quality plugin needs an API key, not a sign-in.

Is my data sent elsewhere?

Not to this project. The suite has no server of its own. Each call goes from your machine straight to Google. Tokens, the OAuth client file and the audit log stay in your token directory, ~/.google-services-mcps. The results you get back go to your AI agent, and from there to its model provider, like any tool output.

Does it work with Codex?

Yes. The installer writes the server entries for Codex, OpenCode and Antigravity into each agent's own config file, and a dry run shows every change first. Those agents have no approval hook in this suite, so their approval behaviour is not yet verified in a live session. A client that cannot ask for approval gets an error for each change and delete, and the action does not run.

Why do I see approval prompts?

Changes and deletions ask first on purpose. Reads never ask. In Claude Code the prompt is labelled with the plugin, for example [plugin:gmail]. A delete, send or disable also shows an Approve this action? form, so it asks twice. You can change this with the Confirm before changes setting (every-change, destructive-only or off) and with rules in policy.json. A deny rule applies in every mode.

How do I remove everything?

Log out of each login group with gsm logout <group>. Uninstall each plugin with claude plugin uninstall <id>@google-services-mcps --scope user, then remove the marketplace with claude plugin marketplace remove google-services-mcps. Delete the token directory ~/.google-services-mcps by hand, and keep audit.log if you need the record. Logging out does not revoke access at Google, so revoke it at myaccount.google.com/permissions, and delete the OAuth client in the Google Cloud console if you no longer need it.
